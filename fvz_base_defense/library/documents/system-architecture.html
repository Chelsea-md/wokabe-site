게임 시스템 구조

게임 규칙과 리소스를 같은 자료로 관리하는 구조

현재 구현을 기준으로 작성 · 로컬 관리 서버와 정적 게임 실행

화면을 그리는 런타임, 공통 규칙, 진행 저장, 리소스 목록을 나눴다. 게임과 설계 라이브러리는 같은 설정과 리소스 목록을 읽는다. 관리 화면에서 저장한 메모와 교체 이력은 작업 폴더의 파일로 남아 사용자와 작업 에이전트가 함께 확인할 수 있다.

게스트 진행강화·코인·해금·챕터를 브라우저에 저장한다.

검증화면 비교와 실제 조작 결과로 변경을 확인한다.

영구 진행과 한 판 상태의 구분

영구 진행전투 세션표시 상태
챕터·코인·기지 체력·생산량·인컴현재 웨이브·자원·기지 남은 체력드래그 위치·보간 위치·안착 시간
병종 해금·튜토리얼·소리 설정배치 병력·적·발사체·획득 코인범위 원·합성·피해·보상 연출
브라우저 저장소에 보관새 판에서 초기화전투 계산과 별개로 부드럽게 표시

기존 저장 키 bloomguard-faithful-v2를 유지했다. 읽을 때 숫자와 배열을 검사하고, 손상된 저장 기록을 읽지 못해도 즉시 원본 기록을 덮어쓰지 않는다. 현재는 진행 중 전투를 재접속해 이어 하는 기능을 제공하지 않으며, 새로고침하면 영구 진행을 유지한 홈으로 돌아온다.

규칙 계산과 조작 처리

  • 배치 후보는 포인터 위치로 결정하고, 실제 구매는 드롭의 유효성과 잔액을 확인한 뒤 적용한다.
  • 합성은 같은 병종·같은 레벨일 때만 적용한다. 체력 계산은 별도 함수라 관찰 결과에 맞춰 바꿀 수 있다.
  • 병력의 논리 위치와 그려지는 위치를 구분한다. 짧은 안착 효과가 구매 판정을 늦추지 않는다.
  • 챕터별 웨이브 수·등장 수·소환 간격·보스 위치를 데이터로 관리한다.
  • 게임의 피해·체력·대상 선택 일부는 아직 런타임 안의 함수로 구성되어 있다. 파일별 분리는 현재 규칙·저장·자료부터 적용했다.

보상 처리 경계

결과 화면 진입 시 기본 보상을 반영하고, 광고 선택을 완료했을 때 추가 보상을 적용한다. 결과를 수령한 뒤 승리라면 다음 챕터로 이동한다. 같은 결과를 이미 벗어난 상태에서는 다시 수령하지 않도록 막는다.

광고 연동 지점

현재 제공자는5초 대기 화면이다. 실제 광고망을 연결할 때는 완료 콜백과 취소·실패를 이 경계에서 처리해야 한다. CrazyGames의 광고·로그인·친구 기능은 연결되어 있지 않다.

리소스 관리와 복구

관리 동작저장되는 위치게임에 미치는 영향
이름·태그·검토 상태·메모data/library-state.json게임 규칙을 바꾸지 않는 협업 기록
새 PNG 추가dist/assets와 공통 리소스 목록미연결 상태로 등록
기존 PNG 교체같은 리소스 파일 경로게임을 다시 열면 새 이미지 사용
교체 전 백업data/revisions/리소스ID이전 이미지를 남겨 복원 가능
과거 이미지 복원현재 파일을 백업한 뒤 선택 버전 적용복원도 새 이력으로 남음

관리 서버는 같은 리소스에 대한 쓰기 작업을 순서대로 처리하고, 완료 파일을 원자적으로 교체한다. 기존 게임 리소스는 ID와 파일 경로를 유지하므로 코드가 다른 이미지 이름을 가리키는 문제를 줄인다. SVG 아이콘은 목록·메모·원본 다운로드로 관리하고, 이 화면의 이미지 교체는 PNG를 대상으로 한다.

현재 공동 관리의 저장 범위는 같은 작업 폴더다. 정적 파일만 여는 환경에서는 문서와 리소스를 볼 수 있지만 서버 저장은 읽기 전용으로 표시된다. 다른 기기의 동시 편집이나 로그인 기반 공유 저장소는 별도 연동 범위다.

변경할 때 지킬 순서

  1. 관찰 근거와 바꾸려는 규칙을 기록한다.
  2. 해당 설정 또는 시스템 함수를 변경한다.
  3. 리소스 변경은 보관함에서 미리 보고 적용한다.
  4. 변경에 맞는 실제 조작 검사와 화면 비교를 수행한다.
  5. 통과한 범위와 아직 남은 가설을 문서에 갱신한다.
